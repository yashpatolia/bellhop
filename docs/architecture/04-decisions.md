# Decisions

Format: ID, decision, reason, consequence. Append; do not rewrite history.

- **ADR-1 Hexagonal layout.** Sponsor access is uncertain (plan risk table), so every external dependency sits behind a port. Consequence: slight indirection, large flexibility.
- **ADR-2 Synchronous ports.** MVP traffic is a few calls; sync keeps tests and services simple. FastAPI runs sync handlers in a threadpool. Revisit if a SpacetimeDB client forces async: wrap it in the adapter.
- **ADR-3 In-memory adapters are first-class.** They are the default runtime for the demo fallback and the test doubles. Consequence: contract tests run against every adapter.
- **ADR-4 Urgency only ratchets up.** Matches the "lean toward escalation" guardrail; enforced in `Call.score`, not in callers.
- **ADR-5 Event bus is in-process and synchronous.** Deterministic tests. A durable bus is not needed for the demo; SpacetimeDB subscriptions serve the dashboard.
- **ADR-6 Pydantic v2 models in the domain.** Same objects serialize to the API and validate input; the one framework dependency allowed in `domain/`.
- **ADR-7 Python 3.12, uv only.** Single toolchain; `uv.lock` committed.
- **ADR-8 Local lexical memory first, Moss second.** Meets the 50 ms budget with zero keys; Moss is an adapter swap if access works.
- **ADR-9 Guard external calls with timeouts and a breaker.** A hung notifier, robot gateway or memory index must not stall a bell press or the voice loop. `adapters/guards.py` runs calls in a small shared thread pool with a deadline (stdlib only). Notifier failures are logged and kept in `failed_alerts` for retry; gateway timeouts raise so the Dispatcher falls back to a nurse; memory recall over budget uses the local fallback and trips a circuit breaker. On by default; `Settings(guard_timeouts=False)` disables. Consequence: a hung call holds a worker thread until it returns. Known limitation: the synchronous event bus does not time-box handlers, so a slow handler still delays `publish`.
- **ADR-10 Facade store, one repository per aggregate.** `InMemoryStore` and `SpacetimeDBStore` expose `.calls .residents .nurses .robots .visits .alerts`, each satisfying its own repository port. Services take only the repository they need; swapping the whole store is one line in the container. Consequence: six small classes instead of one big store port.
- **ADR-11 CallService uses an RLock and stays synchronous.** `score`, `resolve` and `ack_by_nurse` are read-modify-write on a call, and FastAPI runs sync handlers in a threadpool, so a lock guards them. A single lock is fine at demo scale (a few calls). Consequence: no parallelism across calls inside the service; revisit with per-call locks or a real database transaction if traffic grows.
- **ADR-12 Reminiscence from Wikipedia directly, Apify only at ingest.** Measured Apify run: about 12 s for one 45 KB page, far outside the voice loop. MediaWiki's action API gives the same "{year} in music" page in about 0.5 s with no key. `WikipediaContentFeed` is the live source (with local fallback); `ApifyContentFeed` is kept as an optional pre-warm adapter and never runs per utterance.
- **ADR-13 TriageGuard is a backstop, not a classifier.** It takes max(model urgency, keyword floor) and bumps by one for confidence under 0.6, so it can only raise urgency. Measured recall on independent fresh batches was 20/24, 19/24 and 11/24, so phrase lists do not generalise. Gordon's model is the primary classifier; the guard exists so a missed obvious phrase (fall, chest pain) still escalates. Model failure uses `POST /calls/{id}/triage-failed` (urgency 3).
- **ADR-14 API key and CORS are optional settings.** `BELLHOP_API_KEY` turns on `X-API-Key` for every route except `/health`; unset keeps dev and demo frictionless. `BELLHOP_CORS_ORIGINS` narrows allowed origins (default `*`). Consequence: the default deployment is open; setting both is a deployment step, tracked in [11-status.md](11-status.md).
- **ADR-15 SpacetimeDB write-through with an in-memory mirror and fallback.** Reads are served from the mirror; each `save` also POSTs a reducer with a 2 s timeout. Failures are logged and queued (bounded), retried in order, never raised, so the bell path never waits on the network. An unreachable server at build time falls back to the in-memory store. Consequence: the mirror can be ahead of the database; `hydrate()` loads the database into the mirror at startup.
- **ADR-16 A robot idle report is ignored while a call is open.** The Pi reports every 5 s and an `idle` report racing with dispatch would free a robot that is on its way. Battery and room still apply. The call's resolution frees the robot (`Workload`).
- **ADR-17 `GET /alerts` reads from the store.** The alert list is served from `AlertRepository` (the store), not from the notifier's recorded sends; the earlier listing bug was fixed in 8a350a4. Consequence: the list follows whichever store is active.
- **ADR-18 Care data in separate domain and ports modules.** `domain/care.py` and `ports/care.py` (with `InMemoryCareStore`) keep mood, pain, drink, flags, preferences and family messages out of the call aggregate and the main store. Consequence: care data is not yet persisted to SpacetimeDB.
- **ADR-19 Models propose, code decides what memory keeps.** The extractor returns candidate facts with a verbatim quote; `MemoryLearner` drops any whose quote is not in a turn by the claimed speaker, any non-person fact about someone else, and any under a confidence floor, then routes through `MemoryGuard` (review queue under 0.6, health facts always reviewed). Consequence: precision is protected by code we can test, not by prompt wording alone; some true facts are missed or queued.
- **ADR-20 Pick the extraction model by measured accuracy.** `ClaudeFactExtractor` reads its model from `BELLHOP_EXTRACTOR_MODEL`; compare models with `python -m bellhop.labelled.memory_eval --model ...` against the offline `RuleFactExtractor` baseline and keep the most accurate affordable one. Consequence: no model is assumed good; the labelled set must be refreshed with fresh batches to avoid tuning to it.
- **ADR-21 Mock data is a separate service, not a code path in the dashboard.** The dashboard had its own simulator (fake calls, residents, history), so the UI never ran against the real contract. `simulator/` now plays the care home through the backend's public routes (seed, then live bell presses and a robot), and the dashboard reads only the backend. Two environments fall out: `scripts/dev.sh mock` (simulator running) and `scripts/dev.sh empty` (nothing in the home). Consequence: one more process, and the backend gained a few routes only a history import needs (`POST /calls/import`, a `at` on memory and care writes).
- **ADR-22 Provenance lives on the memory fact.** `MemoryFact` keeps `source`, `confidence`, `quote`, `call_id`, `last_confirmed` and `times_seen`; hearing a known fact again counts it instead of only rejecting it. Consequence: the dashboard can show where a fact came from and how often it was heard. Facts are still held by the local index only, not by SpacetimeDB.
- **ADR-23 Staff notes are tidied on the backend, saved only after review.** `POST /residents/{id}/notes/refine` (rule based, or Claude with `BELLHOP_REFINER=claude`, falling back to the rules on any failure) returns wording and what changed; the dashboard shows it, staff edit it, and only then does it go to `/memory` (source `staff`) or `/medical/entries`. The model never writes to the profile directly. Medical history is kept apart from what Bellhop learns and is never changed by the learner.
